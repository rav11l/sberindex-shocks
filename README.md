# Шок по расписанию

Прогноз безналичных потребительских расходов муниципалитетов и раннее обнаружение структурных сдвигов с опорой на календарь решений и новости. Данные — СберИндекс, «Потребительские безналичные расходы на уровне муниципальных образований».

Онлайн-конкурс СберИндекса, 2026, направление «Прогнозирование». Автор — Равиль Ахтямов, Digital Economy Lab.

- Дизайн исследования: [`docs/research_design.md`](docs/research_design.md)
- Первый прогон и что из него следует: [`docs/first_results.md`](docs/first_results.md)
- Отчёт о методологии (черновик): [`report/methodology.md`](report/methodology.md)

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt && pip install -e . --no-deps
python -m sshocks.cli data --download                   # выгрузка с sberindex.ru + сверка sha256
python -m sshocks.cli all                               # данные → прогнозы → детекторы → рисунки
pytest -q tests
```

Модели-основы (Chronos) — отдельно: `pip install -r requirements-foundation.txt`. Нужен доступ к huggingface.co. Без них прогон проходит, модели отмечаются `skipped` в `outputs/forecast_status.csv`.

Любой параметр переопределяется без правки файла:

```bash
python -m sshocks.cli forecast --set forecast.max_series=null data.category=Продовольствие
```

## Что внутри

| Путь | Содержимое |
|---|---|
| `configs/default.yaml` | все гиперпараметры: данные, точки прогноза, модели, детекторы, симуляция новостей |
| `configs/news_rules.yaml` | правила разметки новостей GDELT (без языковых моделей) |
| `configs/foundation.yaml` | прогон Chronos локально, результат объединяется командой `merge` |
| `data/hashes.json` | sha256, размер, адрес и дата выгрузки |
| `data/events/registry.csv` | реестр решений: даты объявления и вступления в силу, география, первоисточник, флаг проверки |
| `src/sshocks/data.py` | загрузка, восстановление рядов одноимённых МО, панель |
| `src/sshocks/news/gdelt.py` | загрузка GDELT с sha256 каждого архива, разметка правилами, выборка для ручной проверки, сверка с реестром |
| `src/sshocks/events.py` | признаки событий и агрегация новостей без заглядывания вперёд |
| `src/sshocks/models/` | `snaive`, `snaive_growth`, `ets_relative`, `prophet`, глобальный `lgbm`, Chronos, TimesFM |
| `src/sshocks/backtest.py` | скользящий бэктест, MAE, R² уровня и прироста, тест Диболда–Мариано |
| `src/sshocks/changepoint/` | детекторы (z-score, панельный, CUSUM, BOCPD с новостной априорной интенсивностью, PELT, BinSeg) и полусинтетическая проверка |
| `outputs/` | таблицы и рисунки прогона (не хранятся в git, воспроизводятся командой `all`) |

Сырые данные СберИндекса в репозиторий не кладутся: их скачивает `data --download`, а совпадение с проверенной выгрузкой подтверждает хеш.

## Первые результаты

Все категории, все 2 016 МО с полной историей, точки прогноза 06–09.2024, горизонты 1–3 месяца, 24 192 пары.

| Модель | MAE, руб. | к Prophet | R² прироста г/г |
|---|---|---|---|
| `ens3_mean` — среднее трёх моделей ниже | 762 | −47 % | 0,42 |
| `factor_only` — контроль: только общий фактор, без моделирования МО | 939 | −34 % | 0,17 |
| `prophet_relative` — Prophet на отклонении от общего фактора | 959 | −33 % | 0,08 |
| `chronos_base` (Chronos-Bolt base, отклонение от общего фактора) | 886 | −38 % | 0,31 |
| `chronos` (Chronos-Bolt small, то же) | 924 | −35 % | 0,28 |
| `ets_relative` | 926 | −35 % | 0,21 |
| `snaive_growth` | 995 | −30 % | 0,12 |
| `lgbm` | 1 338 | −6 % | −0,39 |
| `prophet` (база) | 1 428 | — | −0,71 |
| `snaive` | 4 206 | +195 % | −9,3 |

Главное: почти весь выигрыш даёт перенос сезонности из панели, а не конкретная модель. Контрольная модель `factor_only` без единого обученного параметра уже даёт −34 % к Prophet, а сам Prophet на отклонении от общего фактора — −33 %. Отдельные модели поверх этого приёма статистически неразличимы между собой; устойчивую добавку даёт только ансамбль (−177 руб. к `factor_only`, p = 0,004).

`ets_relative` точнее Prophet в 63 % пар «МО–точка–горизонт» и в 86 % МО. Целевых месяцев всего шесть, поэтому формальный тест слабый: Диболд–Мариано с поправкой на перекрытие горизонтов даёт p = 0,18, а блочный бутстрап по месяцам — интервал от −1 110 до −126 руб. `chronos_base` ещё на 4 % точнее `ets_relative` (p = 0,008), но выигрыш дают крупные МО: по числу МО модели сопоставимы. Тот же Chronos на сыром ряду хуже Prophet на 42 % — решает перенос сезонности из панели, а не класс модели.

Ансамбль лучше любой отдельной модели во всех пяти группах МО по размеру; разрыв с Prophet растёт с размером МО.

Детекторы на полусинтетических шоках (2 016 МО, 3 повтора): лучший — панельный `cross_section`. При сравнении на общей кривой точность–полнота он превосходит остальные на всём её протяжении: при трёх ложных тревогах на 100 ряд-месяцев его полнота 0,60 против 0,48 у PELT и BinSeg. На реальных паводках весны 2024 года общего эффекта в расходах не видно (сдвиг −1,1 п. п. при разбросе 5,6, p = 0,46), и детекторы срабатывают лишь на части затронутых МО.

Подробности и оговорки — в [`report/methodology.md`](report/methodology.md) и [`docs/full_run.md`](docs/full_run.md); разбор работы независимыми судьями и внесённые правки — [`docs/audit_2026-09-18.md`](docs/audit_2026-09-18.md); первый прогон на 400 МО — [`docs/first_results.md`](docs/first_results.md).

## Границы

1. **История 24 месяца.** Прирост г/г существует только за 2024 год. Оценочных пар «точка–горизонт» 12; тест Диболда–Мариано на них слабый, и выводы о превосходстве формулируются по величине разрыва и доле МО, а не по p-значению.
2. **Нет идентификатора ряда и региона.** Ряд восстанавливается по сплошному блоку строк в файле. 726 рядов из 13 140 носят неуникальные названия; сопоставить одноимённые МО между категориями по файлу нельзя.
3. **Региональные события привязываются по названию МО.** Каждое сопоставление проверяется вручную. В модели идут только записи реестра со ссылкой на первоисточник (`verified = yes`); паводок в Оренбурге пока `partial`. Новости GDELT привязываются к МО по транслитерации названия города; одноимённые МО не привязываются.
4. **Настройки Prophet проверены на чувствительность.** Десять конфигураций (гармоники, точки слома, мультипликативная сезонность, логарифм, flat-тренд): лучшая даёт 1 334 руб. против 1 456 у нашей и 932 у `ets_relative`. Разрыв не объясняется настройкой базовой модели (docs/full_run.md, §1б).
5. **Шоки в полусинтетической проверке — ступеньки уровня.** Постепенные изменения и выбросы на один месяц проверяются отдельно. «Чистые» ряды содержат собственные настоящие шоки, поэтому точность детекторов занижена.
6. **Новости в полусинтетической проверке симулированы** (полнота 60 %, 5 % ложных). Это проверка механизма. Реальный поток — GDELT 2023–2024, размеченный правилами без языковых моделей. Это англоязычная пресса (доля российских доменов 0,2 %): федеральные решения в нём почти не видны (1 из 8 решений по ставке), поэтому они берутся из реестра, а поток используется только для ЧС. За два года он дал один локальный шок — паводок апреля 2024. Выборка из 200 новостей просмотрена вручную; отвергнутые человеком адреса лежат в `deny_urls` конфигурации правил.
7. **Модели-основы считаются отдельно** на машине с доступом к весам (`scripts/run_local.ps1`, `configs/foundation.yaml`) и объединяются с основным прогоном командой `merge`; версии пакетов фиксируются по `pip_freeze.txt` этого прогона.
8. **Выгрузка может обновиться.** Хеш фиксирует версию сервера от 25.11.2025; при расхождении прогон предупреждает.
