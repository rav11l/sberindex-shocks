# Шок по расписанию

**Прогноз безналичных потребительских расходов муниципалитетов и раннее обнаружение структурных сдвигов**

Методологический отчёт. Равиль Ахтямов, Digital Economy Lab. Данные — СберИндекс, «Потребительские безналичные расходы на уровне муниципальных образований». Код и конфигурации: [github.com/rav11l/sberindex-shocks](https://github.com/rav11l/sberindex-shocks).

---

## 1. Коротко

Работа отвечает на два вопроса. Насколько точно можно прогнозировать расходы жителей отдельного муниципалитета на один–три месяца вперёд. И можно ли по тем же данным замечать структурные сдвиги в момент их появления.

Три результата.

**Первый. Сезонность нужно брать из панели, а не из истории ряда.** Двух лет наблюдений не хватает, чтобы оценить годовую сезонность по одному МО. Но эта сезонность почти общая для всей страны. Если вычесть из ряда общий фактор — медианную динамику по всем МО — и прогнозировать только отклонение от него, ошибка падает на треть по сравнению с Prophet на том же ряду. Тот же приём решает, а не выбор класса модели: модель-основа Chronos на сыром ряду хуже Prophet на 42 %, а на отклонении от общего фактора — лучше на 38 %.

**Второй. Ансамбль трёх простых моделей точнее любой из них.** Среднее прогнозов Chronos-Bolt на отклонении, ETS на отклонении и наивной модели с поправкой на прирост даёт MAE 762 рубля против 1 428 у Prophet, то есть на 47 % меньше. Выигрыш устойчив: ансамбль лучше в каждой из пяти групп МО по размеру и значим по тесту Диболда–Мариано (p = 0,011).

**Третий, отрицательный. Раннее обнаружение работает не для всякого шока.** Панельный детектор, сравнивающий МО с другими МО того же месяца, находит сдвиги уровня в 10 % и больше с полнотой 0,60 при трёх ложных тревогах на сто ряд-месяцев. Но у реальных паводков весны 2024 года такого следа в месячных расходах нет: средний сдвиг затронутых МО −1,1 п. п. против −0,3 п. п. у остальных при разбросе 5,6 п. п., p = 0,46. Метод честно сообщает, чего он не видит.

Почему этому можно доверять. Все прогоны воспроизводимы: контрольные суммы исходных выгрузок зафиксированы, версии пакетов закреплены, гиперпараметры вынесены в YAML, ни одна модель не видит будущего. Базовая модель проверена на чувствительность к настройкам: ни одна из десяти конфигураций Prophet разрыв не закрывает. Реестр событий состоит только из записей со ссылкой на первоисточник.

## 2. Данные

Выгрузка СберИндекса от 25.11.2025, sha256 `dbe07d6a…15e0f1`, 303 126 строк.

| | |
|---|---|
| Период | 01.2023 – 12.2024, месячная частота |
| Категорий | 6, в каждой 2 190 муниципальных образований |
| Рядов всего | 13 140 |
| Основная категория | «Все категории» |
| Рядов с полной историей 24 месяца | 2 016 |
| Рядов с неуникальным названием МО | 726 |

Три особенности определили весь дизайн.

**Ряд длиной 24 точки.** Годовая сезонность наблюдается один раз. Прирост год к году существует только для 2024 года. Отсюда и главная идея работы, и осторожность в статистических выводах: оценочных пар «точка прогноза – горизонт» всего 12.

**В выгрузке нет идентификатора ряда и региона.** Ряд восстанавливается как сплошной блок строк одного МО и одной категории. У 726 рядов название МО не уникально: одноимённые районы разных регионов различить нельзя. Поэтому события привязываются к МО по названию с явной проверкой, а неоднозначные привязки отбрасываются.

**Уровень расходов между МО различается в разы.** Сравнение моделей идёт и по абсолютной ошибке, и по ошибке в долях от уровня группы МО.

Файл `outputs/data_passport.json` собирается автоматически при каждом прогоне и фиксирует эти цифры.

## 3. Что модель знает в момент прогноза

Прогноз строится из точки T на месяцы T+1, T+2, T+3. В обучение попадают:

- значения ряда по месяц T включительно;
- значения всех остальных МО по месяц T включительно (общий фактор считается по полной панели, а не по выборке);
- события реестра, **объявленные** не позже конца месяца T, с датой вступления в силу в будущем.

Событие датируется моментом объявления, а не вступления в силу: решение по ключевой ставке меняет поведение с даты пресс-релиза, а не с даты применения. Это единственный способ не заглянуть вперёд, когда между объявлением и действием проходят месяцы, как у окончания массовой льготной ипотеки.

Точки прогноза: 06, 07, 08, 09.2024. Все модели считаются на общем наборе пар, метрики сравниваются только на парах, где посчитались все модели: 24 192 пары «МО – точка – горизонт».

## 4. Прогнозные модели

| Модель | Идея |
|---|---|
| `snaive` | значение того же месяца прошлого года |
| `snaive_growth` | то же плюс средний прирост последних трёх месяцев |
| `ets_relative` | ETS на логарифме отклонения ряда от общего фактора панели |
| `chronos` / `chronos_base` | Chronos-Bolt (small / base) zero-shot на том же отклонении |
| `chronos_level` | Chronos-Bolt на сыром ряду |
| `prophet` | Prophet на каждом ряду отдельно, базовая модель конкурса |
| `lgbm` | глобальный градиентный бустинг: поправка к `snaive_growth` по признакам панели и событий |
| `ens3_mean` | среднее прогнозов `chronos_base`, `ets_relative`, `snaive_growth` |

Общий фактор — медиана логарифмов расходов по всем 2 016 МО с полной историей. В нём сидят и сезонность, и инфляция, и общероссийская динамика спроса. Модель на отклонении прогнозирует только то, чем МО отличается от страны, а общий фактор возвращается обратно наивным прогнозом его собственного прироста.

### Результаты, 24 192 пары

| Модель | MAE, руб. | к Prophet | R² прироста г/г | h = 1 | h = 2 | h = 3 |
|---|---|---|---|---|---|---|
| ens3_mean | 762 | −47 % | 0,42 | — | — | — |
| chronos_base | 886 | −38 % | 0,31 | 745 | 869 | 1 043 |
| chronos | 924 | −35 % | 0,28 | 765 | 914 | 1 092 |
| ets_relative | 926 | −35 % | 0,21 | 775 | 906 | 1 096 |
| snaive_growth | 995 | −30 % | 0,12 | 830 | 990 | 1 165 |
| lgbm | 1 338 | −6 % | −0,39 | 1 214 | 1 236 | 1 563 |
| prophet | 1 428 | — | −0,71 | 919 | 1 349 | 2 016 |
| chronos_level | 2 022 | +42 % | −2,78 | 1 598 | 1 581 | 2 888 |
| snaive | 4 206 | +195 % | −9,28 | 4 288 | 4 135 | 4 194 |

Тест Диболда–Мариано против Prophet на 12 парах «точка – горизонт»: ens3_mean p = 0,011, chronos_base p = 0,032, ets_relative p = 0,036. Тест слабый, 12 наблюдений, поэтому он приводится вместе с долей выигранных пар: `ets_relative` точнее Prophet в 63 % пар и в 86 % МО.

Четыре вывода.

1. **R² уровня не различает модели** — у всех, кроме `snaive`, он выше 0,97. Содержательная метрика — R² прироста год к году. У Prophet он отрицательный: на 24 точках Prophet не оценивает годовую сезонность и портит прирост.
2. **Разрыв растёт с горизонтом.** На h = 1 Prophet отстаёт на 14 %, на h = 3 — вдвое.
3. **Глобальный бустинг проиграл простым моделям.** Обучающих точек прироста мало: он доступен только с января 2024 года, а замедление второго полугодия не повторяет первое. Признаки событий вклада не дали (1 338 против 1 325 без них): в окне прогноза все события федеральные и одинаковы для всех МО.
4. **Ансамбль работает, потому что ошибки моделей разной природы.** Chronos переносит форму ряда, `snaive_growth` держится за последние приросты, ETS сглаживает отклонение. Усреднение снимает часть ошибки каждой.

### Ошибка по размеру МО

Группы по среднему уровню расходов за 2023 год, Q1 — самые малые, Q5 — самые крупные. MAE в процентах от уровня группы:

| Модель | Q1 | Q2 | Q3 | Q4 | Q5 |
|---|---|---|---|---|---|
| ens3_mean | 3,96 | 3,38 | 3,00 | 2,51 | 2,32 |
| chronos_base | 4,03 | 3,49 | 3,30 | 3,00 | 3,19 |
| prophet | 6,09 | 5,81 | 5,69 | 5,15 | 4,81 |

Ансамбль лучше во всех пяти группах. Разрыв с Prophet шире на крупных МО.

### Чувствительность базовой модели

Сравнение не должно держаться на неудачной настройке Prophet. Десять конфигураций на общей выборке 400 МО: число гармоник 1, 3, 5; приоритет точек слома 0,01 / 0,05 / 0,5; вовсе без точек слома; мультипликативная сезонность; подгонка на логарифме; плоский тренд.

Лучшая конфигурация — пять гармоник, MAE 1 334 против 1 456 у нашей. Это всё равно на 43 % хуже `ets_relative`. Выигрыш от подбора настроек статистически незначим (p = 0,60). Плоский тренд обваливает Prophet до уровня `snaive`. Ограничение — длина ряда, а не настройка.

### 5.2. Новостной поток

Источник — GDELT 1.0, дневные файлы событий за 2023–2024, 731 архив, 5,9 ГБ, sha256 каждого файла в манифесте. GDELT открыт и бесплатен, платных компонентов в решении нет. Записей с местом события в России 2,69 млн, уникальных статей 736 тыс.

Разметка — правила (`configs/news_rules.yaml`), без языковых моделей: регулярные выражения по адресу статьи, коды CAMEO для ЧС, обязательный российский контекст для федеральных типов, исключение военного контекста. География: страна целиком — федеральная новость, город — МО по транслитерации названия; при совпадении ключа у нескольких МО привязка не делается.

Что дал поток:

- **федеральные решения он не ловит**: из восьми решений по ключевой ставке нашлось одно. Коды CAMEO описывают политические взаимодействия, денежно-кредитная политика в них не кодируется. Доля российских доменов в потоке 0,2 %;
- **к МО привязались 239 новостей**, из них 231 — апрель 2024: Оренбург, Орск, Тюмень. То есть за два года открытый поток дал один локальный шок, и тот уже есть в реестре;
- **ложные срабатывания** видны и после правил: эвакуации военного характера, пожар в театре в статье про «Леди Макбет Мценского уезда». Поэтому 200 новостей проверяются вручную (`data/news/gdelt_review.csv`), и точность правил считается по проверенной выборке.

Вывод для методологии: реестр первоисточников — основной канал, новостной поток — подтверждение и уточнение дат. Расширять охват нужно русскоязычными источниками; GDELT их почти не содержит.

### 5.3. Правила согласования

1. Время события — публикация; переход к месяцу по МСК.
2. Месяц СберИндекса помечается первым числом; новость месяца t влияет на целевой месяц t + L, лаг подбирается на обучающем окне.
3. География: РФ — все ряды; МО — по названию, одноимённые не привязываются.
4. Агрегация в счётчики по (ряд, месяц, тип); дубликаты одной статьи схлопываются по ссылке.
5. В детекторах новость не даёт сигнала сама по себе, а лишь повышает априорную интенсивность смены режима.

## 6. Детекторы структурных сдвигов

Детекторы работают не с рублями, а с преобразованием: прирост год к году в логарифмах минус медиана того же месяца по всем МО. Так снимаются общая сезонность и общероссийская динамика, и остаётся только отклонение конкретного МО.

| Детектор | Что сравнивает |
|---|---|
| `zscore` | текущее отклонение с собственной историей ряда |
| `cross_section` | отклонение МО с разбросом по всем МО того же месяца |
| `cusum` | накопленную сумму отклонений |
| `bocpd` | байесовская оценка вероятности нового режима, с новостями как априорной интенсивностью |
| `pelt`, `binseg` | поиск точек разлома на истории до момента t |

### 6.1. Полусинтетическая проверка

В половину рядов вносится ступенька уровня −20, −10, −5, +5, +10, +20 % в случайный месяц окна 04–12.2024, три повтора, 2 016 МО. Тревога считается верной, если она в течение двух месяцев после ступеньки.

| Детектор | Точность | Полнота | F1 | Ложных на 100 ряд-мес. |
|---|---|---|---|---|
| cross_section | 0,56 | 0,56 | 0,56 | 3,5 |
| binseg | 0,31 | 0,67 | 0,42 | 11,6 |
| pelt | 0,30 | 0,69 | 0,42 | 12,2 |
| cusum | 0,23 | 0,64 | 0,34 | 15,3 |
| bocpd + новости | 0,21 | 0,67 | 0,32 | 18,8 |
| bocpd | 0,20 | 0,63 | 0,30 | 18,8 |

Пороги подбирались отдельно: каждый детектор прогнан по сетке своего порога. При одинаковой доле ложных тревог около трёх на сто ряд-месяцев полнота панельного детектора 0,60, у PELT и BinSeg 0,48. Панельный детектор превосходит остальные на всей кривой, а не в удачно выбранной точке.

Полнота зависит от величины шока: ±20 % — 0,93–0,96; ±10 % — 0,51–0,65; ±5 % — 0,12–0,16.

Новости как априорная информация поднимают полноту BOCPD с 0,63 до 0,67 при той же доле ложных тревог. Механизм работает, но проверен на симулированных новостях (полнота 60 %, 5 % ложных) и на реальных не подтверждён: реальных локальных новостей за два года набралось на один эпизод.

### 6.2. Реальные события

Под пять событий реестра попадают 15 рядов. Событийный анализ: сдвиг отклонения прироста, апрель–июнь минус январь–март.

| | |
|---|---|
| Затронутые МО | 15, средний сдвиг −1,1 п. п. |
| Остальные МО | −0,3 п. п. при разбросе 5,6 п. п. |
| Тест Уэлча | t = −0,76, p = 0,46 |

Разброс внутри затронутых огромен и разнонаправлен: Звериноголовский округ −9,8 п. п., Новотроицк −7,4, Ишим −5,0, при этом Сладковский район +3,8 и Макушинский +3,5. Экономическое объяснение простое: эвакуация и порча имущества расходы снижают, выплаты пострадавшим и восстановительные покупки поднимают, в месячной сумме силы гасят друг друга.

Детекторы ловят часть затронутых рядов: z-score 47 %, PELT и BinSeg 27 %, панельный 13 %. Порядок обратный полусинтетическому. Это не довод в пользу z-score: реальные шоки этого типа по величине сравнимы с обычным разбросом ряда, поэтому их ловит только детектор с низким порогом, а вместе с ними и шум.

## 7. Экономическая интерпретация

**Потребление в муниципалитетах движется общим фактором.** Доля общей динамики в изменчивости ряда настолько велика, что модель, знающая только «как ведёт себя страна» и «чем это МО обычно отличается», обыгрывает модель, которая изучает ряд МО по отдельности. Для практики это означает: прогноз по муниципалитету нужно строить не отдельно, а в панели.

**Крупные МО предсказуемее в относительном выражении.** Ошибка ансамбля падает с 3,96 % уровня в группе малых МО до 2,32 % в группе крупных. Малые МО шумнее: меньше держателей карт, выше роль отдельных крупных покупок.

**Федеральные решения одинаковы для всех и потому бесполезны как признак.** Пока событие общероссийское, оно уходит в общий фактор целиком. Признаки событий начинают работать только тогда, когда событие различает МО между собой. В нашем окне такого события не нашлось.

**Локальные бедствия не оставляют однозначного следа в месячных расходах.** Это содержательный результат, а не неудача метода: для мониторинга нужны шоки, меняющие уровень расходов заметно сильнее собственного разброса МО, — закрытие градообразующего предприятия, крупные выплаты, резкое изменение доступности торговли.

## 8. Границы применимости

1. **24 месяца истории.** Прирост год к году есть только за 2024 год; оценочных пар «точка – горизонт» 12, тест Диболда–Мариано на них слабый, поэтому выводы формулируются по величине разрыва и доле выигранных МО.
2. **Нет идентификатора ряда и региона**; 726 рядов носят неуникальные названия, одноимённые МО между категориями сопоставить нельзя.
3. **События привязываются к МО по названию**; каждая привязка проверяется вручную, в модель идут только записи со ссылкой на первоисточник.
4. **Шоки в полусинтетической проверке — ступеньки уровня.** Постепенные изменения и однократные выбросы проверяются отдельно. «Чистые» ряды содержат собственные настоящие шоки, поэтому точность детекторов занижена.
5. **Новости в проверке детекторов симулированы**; реальный поток GDELT покрывает российские местные СМИ плохо.
6. **Chronos требует внешних весов** с huggingface.co; без них прогон проходит, модель помечается пропущенной. Ансамбль без Chronos (`ens_ets_snaive`) даёт 793 руб. — на 4 % хуже, но не требует внешних зависимостей.
7. **Выгрузка может обновиться**; хеш фиксирует версию, при расхождении прогон предупреждает.

## 9. Воспроизведение

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt && pip install -e . --no-deps
python -m sshocks.cli data --download        # выгрузка + сверка sha256
python -m sshocks.cli all                    # данные → прогнозы → детекторы → рисунки
python -m sshocks.cli analyze                # ансамбли и разрез по размеру МО
python -m sshocks.cli sweep                  # кривые точность–полнота детекторов
```

Модели-основы считаются отдельно на машине с доступом к huggingface.co (`configs/foundation.yaml`, `scripts/run_local.ps1`) и объединяются с основным прогоном командой `merge`. Новостной поток — `python -m sshocks.cli news --download`.

Всё поведение задаётся YAML-конфигурациями, любой ключ переопределяется из командной строки. Версии зависимостей закреплены, зерно случайности фиксировано, контрольные суммы внешних выгрузок записаны в репозитории.
